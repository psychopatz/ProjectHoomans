## Product objective and exact division of responsibility

Make the EXISTING Semantic Lab Studio + Simulation a reusable, inspectable visual authoring environment for registered dialogue/interaction building blocks: create/edit nodes and typed connections; compose a canonical interaction; preview compiled Lua and EN/TL assets; explicitly approve; generate to actual mod media; restart the real Core+Hoomans Lua worker; converse and inspect the *final NPC reply*, Knowledge/dossier evidence, translation/fallback and effects. A new interaction should primarily require authored CodeBlocks, registered data and localized content, not a new collection of manually scripted parser phrases.

Maintain source owners:
- `tools/semantic_harness/workflow.py`: existing Tk Studio/workflow UX; `codebuilder/{blocks,codeblocks,interaction_spec,service,compiler,build}.py`: registry/typed authoring/validation/compiler/writer. `SemanticLabAuthoringService` remains ONE API for GUI, CLI and agent. Keep `semantic.interaction_spec.v1` canonical for typed dialogue/interaction; preserve `semantic.codeblocks.v1` legacy action-flow round trips via compatible graph adapter, not duplicate source-of-truth schemas.
- PsychopatzCore owns semantic parser/IR and `PsychopatzCustomTranslationManager`; Hoomans `PNC.Translation` already wraps registered catalogs. Hoomans runtime owns response planning, game action admission, Quest/Knowledge/Relationships, identity-seeded backstory, sparse deltas, NPC dossier and PBrainZ permissions.
- `Memory.GetBackstoryText()` and legacy text JSON currently translate some fact *values* via `PNC.Conversation.TextLoader`; full sentences already resolve through registered Core-backed translation. Consolidate newly authored semantic fact-value lookups under the registered Core-backed facade with backward-compatible migration, without deleting or breaking historic Conversation Block/backstory consumers.
- Player Knowledge is sparse, server-authoritative and player-character scoped. Seed-derived NPC truth is not player knowledge. All outgoing client, dossier and PBrainZ projections require valid permission; suspected observed rumors never silently upgrade to canonical truth.
